pdd-callback-test · 程序调用关系时序图

拼多多开放平台「企业 ERP」回调最小示例 · Go 标准库实现（server.go / pdd.go / store.go / config.go / main.go）

一、站点间通信拓扑

三方角色：商家浏览器（用户端）、本地服务（:8080 单进程，内含 Server / PddClient / Store）、拼多多开放平台（授权页 + API 网关）。跨站流量只有两条：浏览器 ↔ 授权页的页面跳转，本地服务 ↔ API 网关的接口调用。

二、启动初始化调用时序

纯本地顺序调用，无网络参与。main() 先读配置（loadConfig 会补全空字段默认值），再依次构造 TokenStore、PddClient、Server，最后注册路由并阻塞监听。

三、商家授权回调（跨站）时序

全链路涉及三个站点。关键点：state 由本地生成、内存存放、回调时一次性消费（Consume 即删除，防重放）；code 只能用一次，换来 token 后立即写入 data/tokens.json。授权页只在浏览器侧流转，本地服务不直接访问 mms.pinduoduo.com。

四、订单查询与 Token 刷新时序

alt 分支表示「临近过期才刷新」：ExpiresAt() - now ≤ 300s 才走 ④~⑧，否则直接跳到 ⑨。刷新与查询共用同一个网关入口，仅 type 不同（token.refresh / order.list.get）。

说明

  • 实线箭头为调用/请求，虚线箭头为返回值。
  • 所有外发请求都走 PddClient.doRequest，统一做参数拼装 + MD5 大写签名（sign()，跳过空值），10s 超时。
  • 网关返回若含 error_response 字段，会被直接当错误抛出。
  • state 存内存（StateStore，10 分钟 TTL），token 落盘（data/tokens.json，0600 权限）。示例为明文存储，生产需加密 + Redis/Session。
